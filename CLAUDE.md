# Retail — памятка для Claude Code

Этап проектирования антифрод-решения для ритейла на Интеллект X: кассовые данные и КСО, титры чеков на видео, сценарии корреляции POS- и видеособытий, конструктор правил, инциденты, отчёты. Production-кода нет. Обзор и как смотреть прототипы — [README.md](README.md).

## Источник истины

- **ТЗ** — [Technical_Specification_v3.MD](Specification/Technical_Specification_v3.MD), версия 3.0, действующая. Журнал изменений версии — §20 ТЗ. Сценарии — `POS-NN`, `RETAIL-NN`, `ANL-NN`, `LOG-NN` (заголовки §10); в скобках — номера пунктов исходного ТЗ заказчика (`3.2.x`).
- **Прошлые версии** — `Technical_Specification_v1.MD`, `v2.MD`: не править, не ревьюить, ошибки в них не записывать.
- **Входные документы** (`Specification/*.docx`, `*.xls`) — не правятся:
  - «Техническое задание Ритейл — правки» (2026-09-07, 2026-09-17 Сизов) — уже учтены в v3 (§1, §20);
  - «2026-10-25 Разработка интерфейса» — требования к интерфейсу ITV Special Solution / Retail Solution 2.0, в ТЗ ещё **не внесены**. Расхождение прототипа с ТЗ, которое объясняется этим документом, — вопрос в таблицу решений, а не `BUG`;
  - «Retail Solution (сроки).xls» — план-график.
- **Прототипы** — `prototype/index.html` (полный, по умолчанию тёмная тема) и `prototype/short_version.html` (упрощённый, переключатель темы). Общие: редактор сценариев `scenario-editor.js` / `.css`, переводы ru / en — `i18n.js` (ключ — русская строка). Расходятся с ТЗ — верно ТЗ, кроме случая выше.
- **Оформление** — ONE PSIM: `bridge.css` (маппинг на `--one-*`) и `theme/` скопированы из `../ONE.PSIM.PrototypeKit`; `theme/` руками не править — источник в ките, правила — его `docs/RESTYLE-RULES.md`. Лестниц, которых нет в ките, не выдумывать — пробелы записаны в README («Пробелы правил»).
- **Жизненный цикл инцидента** (§9.2, компонент Incident Manager в §5.1) пересекается с проектом IM (`../IM`). Расхождение статусов и действий с IM — вопрос архитектору в таблицу решений; IM не править.
- Ревью и планы — `reviews/<дата>/`, порядок и нумерация — [reviews/README.md](reviews/README.md).

## Сгенерированные файлы — руками не править

`theme/one-psim.css`, `theme/native.css` — копии из `../ONE.PSIM.PrototypeKit`, обновляются оттуда.

## Проверки

Быстрые — после любой правки (на Windows `python`, на Linux `python3`):
`python tools/kit/check_links.py`, `python tools/kit/check_ids.py`.

| Поменял | Дополнительно |
|---|---|
| ТЗ | `check_ids.py --unused` — сценарии, на которые нет ссылок из других разделов, прототипов или README |
| прототипы, `scenario-editor.*`, `bridge.css` | `python tools/kit/check_page.py` (оба прототипа, обе темы, 1440 и 360 px; `--shots <scratchpad>` — снимки) |
| строки интерфейса | в `i18n.js` есть перевод каждой новой строки на английский |

Прототип можно открыть и сервером (`npx http-server . -p 4174 -c-1`, README) — так `theme/*.css` гарантированно резолвятся из `bridge.css`.

Параметры проверок — `.claude/kit.json`, описание — [tools/kit/README.md](tools/kit/README.md). Не прогнал проверку — так и сказать, с причиной.

## Договорённости

- Перед правкой — `git fetch`; есть новое на GitHub — предложить подтянуть.
- Коммит и push — только по просьбе. Коммитов на пункт плана два: исправление (`BUG-01: …` — сообщение начинается с номера пункта) и отметка `[x]` с хэшем в `plan.md` (`Хэш <коммит> в плане ревью <дата>`).
- Пункт из таблицы решений плана — в работу, только когда заполнено «Решение».
- Правка ТЗ — в действующем файле, с записью в §20; новая версия — новый файл `Technical_Specification_v<N>.MD`, только по просьбе.
- Изменение общего модуля редактора сценариев проверять в обоих прототипах.
- Язык документов и сообщений коммитов — русский, простыми словами; строки интерфейса — на двух языках.

## Скиллы

`/retail-review [роль]` — ревью ТЗ и прототипов; `/retail-fix <пункт>` — выполнить пункт плана. Оформление под ONE PSIM — скилл `one-psim-restyle`, если подключён. Общие файлы скиллов и `tools/kit/` приходят из ClaudeKit (`../ClaudeKit`, версия — `.claude/kit.json`): правятся там и переносятся командой `python ../ClaudeKit/apply.py update .`. Своё для проекта — этот файл, чек-лист [.claude/skills/retail-review/checklist.md](.claude/skills/retail-review/checklist.md), `.claude/kit.json`, `.claude/evals/triggers.md`.
